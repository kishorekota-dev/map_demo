# Optional Dialogflow integration

The active wrapper is [dialogflow.service.js](src/services/dialogflow.service.js), configured through [src/config/config.js](src/config/config.js). It uses the installed `@google-cloud/dialogflow` SessionsClient for intent detection. The enhanced SDK module and older SDK implementation reports are exploratory/historical, not the mounted request path.

Set `DIALOGFLOW_ENABLED=true` and `DIALOGFLOW_PROJECT_ID` for an enterprise-owned project. Inject `DIALOGFLOW_CREDENTIALS_JSON` into the server environment with service-account JSON containing `type:"service_account"`, `client_email`, and a valid RSA `private_key`. Never commit credential values or send them in a client request. The server explicitly selects the email and private key for the SDK's [documented credentials option](https://github.com/googleapis/google-cloud-node/blob/main/docs/authentication.md); other JSON fields cannot override authentication endpoints. `DIALOGFLOW_LANGUAGE_CODE` defaults to `en-US`. Check the exact active environment mapping before deployment.

This is a breaking authentication hardening: the wrapper no longer reads `DIALOGFLOW_KEY_FILENAME`, `GOOGLE_APPLICATION_CREDENTIALS`, or ambient Application Default Credentials. Enabled providers with missing/invalid project credentials fail startup. SDK initialization and live call failures are not converted into mock success. Status `configured` proves only initialization; it does not verify credentials remotely, deployed intents, permissions, accuracy, or an enterprise environment/version rollout.

When disabled outside production, the wrapper retains explicit demo responses. Production never serves those mock responses; `/dialogflow` and the combined `/analyze` path return a safe 503 if the provider is disabled/unavailable. The `/intents` pipeline continues its deterministic local fallback on optional provider failures. Configured credential values are redacted from provider results before returning them. Qualify an enterprise-owned project in staging before production use; no live Google project was exercised by the fixture tests. The unmounted enhanced SDK demonstration is disabled in production.

Legacy agent JSON assets in [dialogflow-config](dialogflow-config/) are optional import inputs, not evidence of a current deployment. Review them against the canonical vocabulary before using an authorized enterprise console import. Runtime `/train` does not train or deploy an agent.

The published orchestrator catalog remains authoritative when control-plane governance is enabled. Its external/LLM recognition strategy is a separate contract. See [NLU API](API-EXAMPLES.md), [deployment procedure](DIALOGFLOW-DEPLOYMENT-GUIDE.md), and [governed recognition](../ai-orchestrator/CONTROL-PLANE-RUNTIME.md#recognition).
